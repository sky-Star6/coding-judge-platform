# 온라인 코딩 저지 플랫폼 문제 제작 및 DB 등록 스킬 (judge-problem-creator)

이 스킬은 플랫폼의 급수별 난이도 체계, 언어 표준(Python 3, Java 17), 주석 규칙, 테스트 케이스 검증 및 안전한 데이터베이스 등록 절차를 정의합니다.

---

## 1. 급수 및 난이도 매핑 체계

| 급수 구분 | DB `difficulty` | 문제 ID 범위 | 출제 방식 및 주요 특징 |
| :--- | :---: | :---: | :--- |
| **입문/기초** | `0` | 1 ~ 135번+ | **[사용자 완성 코드 기반]** 전달받은 코드를 바탕으로 문제 설명, 빈칸/코딩, 테스트 케이스 구성 후 DB 반영 |
| **3급 테스트** | `1` | 1 ~ 50번+ | **[AI 창작]** 기초 구현, 단순 반복문/조건문, 기본 문자열 및 리스트 다루기 |
| **2급 테스트** | `3` | 1 ~ 120번+ | **[AI 창작 (COS Pro 2급 표준)]** 실생활 스토리텔링 시나리오, `def solution(...)` 함수형, **한 줄 디버깅(`debugging`)** 및 빈칸 조립(`blank`). (단, 빈칸 조립형은 `func_a` 나열 대신 `### 단계` 아래 `1. 설명`, `2. 설명` 순서로 기술) |
| **1급 테스트** | `5` | 1 ~ 109번+ | **[AI 창작]** 실전 알고리즘/자료구조 (탐욕법(Greedy), 스택/큐, 정렬, 투 포인터, 시뮬레이션 등) |

## 2. 코드 및 주석 작성 원칙 (절대 규칙)

### ① 학생용 초기 코드 (`initial_code_python`, `initial_code_java`)
* **주석을 일체 작성하지 않습니다.** (주석 완전 제거)
* 학생이 주석 힌트에 의존하지 않고, 순수하게 코드의 제어 흐름과 로직을 직접 분석할 수 있도록 합니다.

### ② 해설 및 정답 코드 (`answer_python`, `answer_java`)
* 초보자도 이해할 수 있도록 **매 줄마다 아주 상세한 한국어 주석**을 작성합니다.
* 기술 용어는 **한국어와 영어를 병기**합니다 (예: 나머지 연산자(Modulo Operator, %), 순회(Traverse)).
* 파이썬은 **PEP 8 표준** 및 명확한 변수명(`snake_case`), 자바는 **카멜케이스(`camelCase`)**를 엄격히 준수합니다.
* 디버깅/빈칸 문제의 정답 포인트는 **`[[정답]]`** 이중 대괄호로 표기합니다.

### ③ Java 17 표준 준수
* 모든 문제는 **Python 3**과 **Java 17** 버전 코드가 1:1 세트로 반드시 함께 제작되어야 합니다.
* 자바 클래스는 채점 엔진 규격인 `public class Main`을 엔트리 포인트로 작성합니다.
* `supported_languages` 컬럼은 `'python3,java'`로 지정합니다.

```markdown

### ■ 예제 설명
```

## 4. 테스트 케이스 설계 및 사전 검증

1. **테스트 케이스 구성**:
   * 공개 예제 (`is_public = 1`): 1~2개 (문제 본문에 표시)
   * 비공개 채점용 (`is_public = 0`): 3개 이상 (코너 케이스, 경계값 포함)
2. **사전 채점 검증 (필수)**:
   * 정답 코드가 모든 테스트 케이스를 100% 통과(AC)하는지 파이썬/자바로 미리 실행 검증합니다.
   * 디버깅 문제의 경우, 버그가 있는 초기 코드가 준비된 테스트 케이스에서 정상적으로 오답(WA)을 내는지 확인합니다.
   * 한 줄 디버깅 문제(`debugging`)의 경우 초기 코드와 정답 코드의 라인 차이가 2 이하(1줄 삭제, 1줄 추가)여야 합니다.

## 5. 데이터베이스(`judge_db.sqlite`) 안전 반영 절차

1. **백업 생성**: 작업 전 반드시 타임스탬프가 포함된 백업본(`judge_db_backup_YYYYMMDD_HHMMSS.sqlite`)을 생성합니다.
2. **Display ID 채번**: 해당 난이도(`difficulty`)의 `MAX(display_id) + 1`로 자동 부여합니다.
3. **INSERT 실행**:
   * `problems` 테이블: `display_id, title, description, difficulty, initial_code_python, initial_code_java, answer_python, answer_java, problem_type, supported_languages` 등록
   * `test_cases` 테이블: 생성된 `problem_id`와 연결하여 입출력 데이터 등록
4. **검증 및 조회**: 반영 후 SELECT 쿼리로 정상 등록 여부를 확인하고 사용자에게 최종 보고합니다.
