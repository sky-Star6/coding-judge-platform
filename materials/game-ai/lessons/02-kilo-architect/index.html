코딩 전에 설계도부터! Kilo Architect로 깔끔한 게임 폴더 만들기 📐

1강에서 만든 index.html 한 파일에 캐릭터, 몬스터, 사운드를 다 우겨 넣으면 금방 500줄이 넘어 AI도 길을 잃습니다. 오늘은 Kilo Architect 모드로 SPEC.md 설계도를 먼저 작성하고, 역할별로 파일을 깔끔하게 나누는 방법을 배웁니다!

SPEC.md 설계도

.kilorules 안전 규칙

Kilo가 내 코딩 스타일과 한국어 주석 약속을 매번 기억하게 만들기

멀티 파일 모듈 분리

🏗️ 왜 설계도와 모듈 분리가 중요할까요?

AI 코딩 에이전트와 협업할 때 가장 큰 실수는 "설계 없이 한 파일에 계속 기능을 추가하는 것"입니다.

Architect 모드

🧸 어린이 비유: 레고 성을 쌓기 전에 설명서와 부품 목록표부터 먼저 그려주는 건축가!

🎓 개발자 원리: 코드를 바로 고치지 않고 요구사항을 분석해 파일 구조와 작업 순서를 계획합니다.

.kilorules 규칙

🧸 어린이 비유: AI 파트너의 책상 위에 붙여두는 "절대 어기면 안 되는 작업 약속 메모지"!

🎓 개발자 원리: 프로젝트 루트의 .kilorules를 읽어 매 대화마다 일관된 코드 규칙을 적용합니다.

모듈 분리 (Module)

🧸 어린이 비유: 양말, 바지, 티셔츠를 한 서랍에 다 섞지 않고 칸칸이 나누어 정리하는 옷장!

🎓 개발자 원리: import / export로 파일을 나누면 버그를 찾을 때도 한 파일만 열면 됩니다.

주니어 개발자 제2원칙: "코드를 수정할 때 파일이 짧고 역할이 분명할수록, Kilo가 실수할 확률은 10배 줄어듭니다!"

STEP 0. 1강 폴더 이어받기 & Architect 모드 전환

          VS Code에서 1강 작업 폴더(.kilorules, SPEC.md, index.html)를 연 뒤, QUEST 01에서는 Kilo 모드를 Architect로 바꾸고 실행하세요.
        

      


      


        
        

          

            

              Architect 모드
              

                
QUEST 01. @SPEC.md 설계도 완성 & 분리 계획 세우기

                코딩 전 아키텍처 설계
              

            

            
          

          
[Mode: Architect]

[Goal]:
@index.html 과 @SPEC.md 를 읽고, 앞으로 12강까지 확장하기 좋게 파일을 분리하는 설계도를 제안해 줘.

[Condition]:
1. 아직 코드는 수정하지 말고, style.css / js/main.js / js/player.js 3개 파일로 나눌 때 각 파일이 맡을 역할만 정리해 줘.
2. 내가 만들 게임 테마(예: 우주 별똥별 피하기 또는 네온 던전)에 맞춰 @SPEC.md 의 1번 항목을 채우는 초안을 보여줘.

        


        
        

          

            

              Code 모드
              

                
QUEST 02. @index.html에서 디자인(style.css) 분리하기

                HTML과 CSS 역할 분리
              

            

            
          

          
[Mode: Code]

[Goal]:
@index.html 안에 들어있는 <style> 태그 내용을 새 파일 style.css 로 분리하고, @index.html 에서 <link rel="stylesheet" href="style.css"> 로 연결해 줘.

[Condition]:
1. 화면 디자인이나 캔버스 크기가 1강과 똑같이 유지되어야 해.
2. 작업 후 Live Server에서 화면이 깨지지 않는지 확인할 수 있게 알려줘.

        


        
        

          

            

              Code 모드
              

                
QUEST 03. js/main.js & js/player.js 모듈로 쪼개기

                ES Module (import / export) 적용
              

            

            
          

          
[Mode: Code]

[Goal]:
@index.html 의 <script> 코드를 js/main.js 로 옮기고, 공(또는 플레이어) 객체와 이동/그리기 로직은 js/player.js 로 분리해 줘.

[Condition]:
1. @index.html 에서는 <script type="module" src="js/main.js"></script> 로 연결해 줘.
2. js/player.js 는 Player(또는 Ball) 클래스를 export 하고, js/main.js 에서 import 해서 사용해 줘.
3. .kilorules 규칙에 따라 기존 1강 기능(60FPS 루프, 클릭 추가, 일시정지)이 모두 그대로 동작해야 해.

        


        
        

          

            

              문서 동기화
              

                
QUEST 04. @SPEC.md 진행 상황 업데이트하기

                설계도와 실제 코드 일치시키기
              

            

            
          

          
[Mode: Code]

[Goal]:
지금까지 완성된 @index.html @style.css @js/main.js @js/player.js 구조를 반영해서 @SPEC.md 를 업데이트해 줘.

[Condition]:
1. 1강과 2강 체크박스를 [x] 완료 표시로 바꿔줘.
2. 현재 프로젝트 폴더 트리도 @SPEC.md 아래에 정리해 줘.

        


        
        

          

            

              Ask 모드
              

                
QUEST 05. 내 코드 구조 이해하고 점검하기

                모듈 간 연결(import/export) 복습
              

            

            
          

          
[Mode: Ask]

[Goal]:
@js/main.js 와 @js/player.js 가 서로 어떻게 데이터를 주고받는지 중학생 눈높이에서 3단계로 설명해 줘.
그리고 3강에서 방향키 이동과 점프 물리를 추가할 때 @js/player.js 의 어느 함수에 코드를 넣어야 하는지 알려줘.

📐 아키텍트 모드

              Architect Mode
            

            

              🧸 어린이 비유: 집을 짓기 전에 방 배치도와 설계도부터 먼저 그리는 건축가 모드!
            

            

              🎓 개발자 정의: 실제 코드를 수정하기 전에 시스템 구조, 파일 분리, 구현 계획을 수립하는 설계 전용 모드.
            

          


          

            

              
🧩 모듈 분리

              Modularization (ES Modules)
            

            

              🧸 어린이 비유: 거대한 한 덩어리 코드를 기능별 레고 블록(파일)으로 쪼개서 조립하는 것!
            

            

              🎓 개발자 정의: import / export 문법으로 코드를 독립된 파일 단위로 나누어 재사용성과 유지보수성을 높이는 기법.
            

          


          

            

              
📋 명세서

              Specification (SPEC.md)
            

            

              🧸 어린이 비유: "무엇을 만들지" AI와 내가 함께 보며 확인하는 게임 기획서!
            

            

              🎓 개발자 정의: 프로젝트의 목표, 기능 목록, 기술 제약 조건을 마크다운으로 정리한 기준 문서.
            

          


          

            

              
🛡️ 프로젝트 규칙

              Project Rules (.kilorules)

              🎓 개발자 정의: AI 에이전트가 코드를 생성·수정할 때 자동으로 따르는 프로젝트 단위 지침 파일.
