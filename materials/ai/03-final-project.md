# 최종 프로젝트 운영안

## 목표

학생이 자신의 문제를 선택하고 AI와 협업해 실제로 동작하는 결과물을 만든다. 평가는 코드 양보다 기획, 선택 근거, 테스트, 수정, 설명을 중시한다.

## 허용 프로젝트 예시

- 웹게임, 학습 도구, 퀴즈, 일정·습관 관리
- 학교생활 도구, 간단한 자동화, 공개 데이터를 활용한 웹앱
- 키 없이 작동하거나 무료 사용 범위 내 AI 기능을 선택적으로 결합한 웹앱
- 학생이 정의한 작은 웹서비스

개인정보를 불필요하게 수집하거나, 유료 서비스 없이는 시연할 수 없거나, 4주 안에 핵심 기능을 끝내기 어려운 주제는 범위를 줄인다.

## 19–24주 산출물 게이트

| 주차 | 게이트 | 통과 기준 |
|---:|---|---|
| 19 | 제안 승인 | 사용자·문제·근거·핵심 가치가 한 문단으로 설명됨 |
| 20 | 설계 승인 | 핵심 흐름, 와이어프레임, 필수 기능, 완료 조건, 위험이 있음 |
| 21 | 알파 | 핵심 사용자 흐름 하나가 처음부터 끝까지 작동함 |
| 22 | 베타 | 필수 기능과 주요 오류 처리가 작동하고 버그 기록이 있음 |
| 23 | 출시 후보 | 사용자 테스트 후 핵심 문제를 수정하고 재시험함 |
| 24 | 발표 완료 | 라이브 또는 백업 데모, 테스트 증거, 한계, 회고를 발표함 |

## 필수 포트폴리오

1. 문제 정의와 대상 사용자
2. 아이디어 후보와 선택 근거
3. 요구사항과 완료 조건
4. 화면·데이터·작업 설계
5. AI에 보낸 주요 프롬프트와 결과 검토 기록
6. 코드 변경 및 버전 기록
7. 오류 재현–가설–수정–재시험 기록
8. 정상·경계·오류 테스트 결과
9. 사용자 테스트와 개선 전후
10. 완성 결과물, 한계, 다음 버전 계획

## 평가 루브릭

각 영역을 1–4점으로 평가한다.

| 영역 | 1점 | 2점 | 3점 | 4점 |
|---|---|---|---|---|
| 문제 정의 | 문제·사용자 불명확 | 일부 설명 | 사용자와 상황이 명확 | 근거로 가정을 검증 |
| 계획·분해 | 작업 구분 없음 | 큰 단계만 있음 | 순서·완료 조건 명확 | 위험·우선순위까지 관리 |
| AI 협업 | 결과를 그대로 사용 | 일부 질문·수정 | 범위 지시와 검토 수행 | 제안을 비판적으로 선택·설명 |
| 구현 | 핵심 흐름 미작동 | 부분 작동 | 핵심 흐름 안정 작동 | 예외·접근성까지 고려 |
| 테스트·디버깅 | 증거 없음 | 성공 사례 위주 | 정상·경계·오류 검증 | 회귀·사용자 재시험까지 수행 |
| 설명·회고 | 결과만 소개 | 과정 일부 소개 | 선택·실패·수정을 설명 | 한계와 다음 개선을 근거로 제시 |

총점만으로 순위를 매기기보다 영역별 성장 피드백을 제공한다. 코딩 경험자는 기능 수가 아니라 검증·구조·접근성 기준을 더 높게 적용한다.

## 발표 형식

- 0:00–0:40 문제와 사용자
- 0:40–1:20 해결 아이디어와 핵심 선택
- 1:20–3:20 작동 데모
- 3:20–4:15 AI 협업, 오류, 테스트와 개선 증거
- 4:15–5:00 한계와 다음 단계
- 이후 3분 질의응답

## 발표 전 체크리스트

- 핵심 흐름을 새로고침 후 다시 실행했다.
- 인터넷 또는 API 실패 시 사용할 로컬 대체 자료가 있다.
- 개인정보와 API 키가 화면·코드·기록에 없다.
- AI가 만든 부분과 내가 확인·수정한 부분을 설명할 수 있다.
- 알려진 한계와 다음 개선 항목을 숨기지 않는다.
- 데모 실패에 대비한 스크린샷 또는 짧은 녹화가 있다.
