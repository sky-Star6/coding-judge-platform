# 24주 AI·코딩 교육과정

## 과정 개요

- 대상: 중학생 이상, 코딩 무경험자부터 기초 경험자
- 기간: 24주, 주 1회, 회당 120분
- 기본 환경: 웹 브라우저, 텍스트 편집기, 터미널, 무료 AI 도구 또는 Codex CLI
- 공통 수업 흐름: 개념 → 시연 → 실습 → 문제 해결 → 결과물 → 공유·회고
- 시간 권장안: 도입·복습 10분, 개념 20분, 시연 20분, 실습·미션 50분, 공유·회고 15분, 정리 5분
- 평가: 정답 코드보다 문제 정의, 검증 과정, 수정 기록, 설명 능력을 함께 본다.

## 단계별 로드맵

| 단계 | 주차 | 핵심 성취 |
|---|---:|---|
| AI 리터러시와 프롬프트 | 1–4 | AI의 작동 방식과 한계를 이해하고 요청을 구체화한다. |
| 웹 코딩 기초 | 5–9 | HTML·CSS·JavaScript로 작은 웹 결과물을 만든다. |
| AI 협업 개발 | 10–14 | 요구사항, 분해, Codex CLI, 디버깅, 테스트를 경험한다. |
| 프로젝트와 에이전트 | 15–18 | 데이터를 다루고 에이전트·역할 분담 워크플로우를 설계한다. |
| 최종 프로젝트 | 19–24 | 기획부터 구현, 검증, 개선, 발표까지 완주한다. |

## 1주차 — AI는 무엇을 잘하고 무엇을 틀릴까

- 학습 목표: 생성형 AI의 입력·생성·출력 구조를 설명하고, 사실과 그럴듯한 답을 구분한다.
- 핵심 개념: 생성형 AI, 프롬프트, 확률적 생성, 환각, 개인정보 보호.
- 교사 설명: AI를 “많은 예시에서 다음 내용을 예측하는 도구”로 소개하고 검색·계산기와 차이를 비교한다.
- 시연: 같은 질문을 표현만 바꿔 세 번 요청하고 답의 차이와 틀린 사실을 함께 찾는다.
- 학생 실습: 관심 주제를 AI에 질문하고 주장 세 개를 표로 정리해 직접 확인한다.
- 실습용 프롬프트: `중학생에게 설명하듯 [주제]를 5문장으로 설명해 줘. 사실 확인이 필요한 문장에는 [확인 필요]를 붙여 줘.`
- 학생 미션: AI가 자신 있게 말하지만 검증이 필요한 답 하나를 찾아 근거와 함께 수정한다.
- 예상 문제: AI 답을 그대로 믿거나 개인정보를 입력한다.
- 문제 해결 방법: 최소 두 근거와 대조하고 개인정보·계정 정보는 가상의 값으로 바꾼다.
- 결과물: AI 답변 검증 카드 1개.
- 복습: AI 답을 확인해야 하는 이유를 한 문장으로 쓴다.
- 확장 과제: 같은 질문을 두 AI에 묻고 공통점·차이·근거를 비교한다.
- 다음 주차 연결: 답의 품질을 높이는 요청 구조를 배운다.

## 2주차 — 좋은 질문이 좋은 결과를 만든다

- 학습 목표: 목적, 대상, 조건, 출력 형식을 포함한 프롬프트를 작성한다.
- 핵심 개념: 맥락, 역할, 제약 조건, 예시, 출력 형식.
- 교사 설명: 모호한 주문과 구체적인 주문을 비교하되 긴 프롬프트가 항상 좋은 것은 아님을 강조한다.
- 시연: “퀴즈 만들어 줘”를 목적·난이도·문항 수·정답 형식이 있는 요청으로 개선한다.
- 학생 실습: 자신이 좋아하는 주제의 5문항 퀴즈를 만들고 친구가 풀어보게 한다.
- 실습용 프롬프트: `너는 퀴즈 출제자야. [대상]이 [주제]를 복습하도록 객관식 5문항을 만들어 줘. 보기 4개, 정답과 한 줄 해설을 별도 표로 제시해.`
- 학생 미션: 첫 결과의 문제를 두 가지 찾아 프롬프트를 한 번 개선한다.
- 예상 문제: 조건이 충돌하거나 원하는 결과 형식을 빠뜨린다.
- 문제 해결 방법: 목적·대상·조건·형식 체크리스트로 요청을 다시 읽는다.
- 결과물: 초안과 개선본이 포함된 프롬프트 비교 기록.
- 복습: 내 결과에 가장 큰 영향을 준 조건을 표시한다.
- 확장 과제: 좋은 예시와 나쁜 예시를 하나씩 포함해 결과 차이를 분석한다.
- 다음 주차 연결: 큰 문제를 AI가 처리할 수 있는 작은 작업으로 나눈다.

## 3주차 — 문제를 작은 작업으로 나누기

- 학습 목표: 목표를 입력·처리·출력과 5개 이하의 작업으로 분해한다.
- 핵심 개념: 문제 정의, 사용자, 요구사항, 작업 분해, 완료 조건.
- 교사 설명: “학교생활을 편하게”와 “준비물을 놓치지 않게”의 범위 차이를 보여준다.
- 시연: 간단한 공부 타이머를 화면, 버튼, 시간 계산, 알림, 테스트 작업으로 나눈다.
- 학생 실습: 학교생활의 불편 하나를 고르고 문제 정의 카드와 작업 목록을 작성한다.
- 실습용 프롬프트: `문제는 [문제]이고 사용자는 [사용자]야. 코딩 초보자가 만들 수 있는 가장 작은 해결책으로 줄이고, 작업을 순서대로 5개 이하로 나눠 줘. 각 작업의 완료 조건도 써 줘.`
- 학생 미션: 친구가 작업 목록만 읽고 결과물을 설명할 수 있게 수정한다.
- 예상 문제: 기능을 너무 많이 넣거나 해결책부터 정한다.
- 문제 해결 방법: “반드시 필요한가?”를 묻고 핵심 기능 하나만 남긴다.
- 결과물: 문제 정의서와 최소 기능 작업 목록.
- 복습: 문제와 해결책의 차이를 예로 설명한다.
- 확장 과제: 기본·선택·나중 기능으로 우선순위를 나눈다.
- 다음 주차 연결: AI 결과를 평가하고 반복 개선하는 방법을 연습한다.

## 4주차 — 생성, 검증, 개선의 반복

- 학습 목표: 평가 기준을 먼저 세우고 AI 결과를 피드백으로 개선한다.
- 핵심 개념: 평가 기준, 구체적 피드백, 반복, 버전, 근거.
- 교사 설명: “별로야” 대신 위치·문제·기대 결과를 말하는 피드백 공식을 소개한다.
- 시연: AI가 만든 안내문을 정확성·명확성·대상 적합성 기준으로 두 번 수정한다.
- 학생 실습: 2주차 퀴즈를 평가표로 테스트하고 오류와 애매한 표현을 고친다.
- 실습용 프롬프트: `다음 결과를 [기준 1], [기준 2], [기준 3]으로 평가해. 문제 위치, 이유, 수정안을 표로 쓰고 확인되지 않은 사실은 따로 표시해: [결과]`
- 학생 미션: 수정 전후의 차이와 수정하지 않은 제안의 이유를 기록한다.
- 예상 문제: AI의 모든 수정 제안을 수용하거나 버전을 덮어쓴다.
- 문제 해결 방법: 변경마다 수용 여부와 이유를 적고 v1·v2를 보존한다.
- 결과물: 평가표와 개선 전후 결과.
- 복습: 좋은 피드백의 세 요소를 말한다.
- 확장 과제: 친구의 결과물을 같은 기준으로 동료 평가한다.
- 다음 주차 연결: AI가 만드는 코드를 이해하기 위한 웹 구조를 배운다.

## 5주차 — 웹페이지의 뼈대, HTML

- 학습 목표: 태그, 요소, 속성의 의미를 알고 의미 있는 HTML 문서를 작성·실행한다.
- 핵심 개념: 문서 구조, 제목, 문단, 목록, 링크, 이미지, 접근성 대체 텍스트.
- 교사 설명: HTML을 건물의 뼈대와 안내 표지에 비유하고 의미에 맞는 태그 사용을 강조한다.
- 시연: 한 파일로 자기소개 페이지를 작성하고 브라우저에서 새로고침한다.
- 학생 실습: 제목, 소개, 관심사 목록, 안전한 링크가 있는 프로필 페이지를 만든다.
- 실습용 프롬프트: `HTML 초보자용 자기소개 페이지 뼈대를 만들어 줘. h1, p, ul, a를 사용하고 각 줄의 역할을 주석이 아닌 별도 설명으로 알려 줘.`
- 학생 미션: AI 코드에서 태그 하나를 바꿔 화면과 의미가 어떻게 달라지는지 기록한다.
- 예상 문제: 닫는 태그 누락, 파일 확장자 오류, 개인정보 공개.
- 문제 해결 방법: 들여쓰기와 브라우저 개발자 도구로 구조를 확인하고 가상 정보를 쓴다.
- 결과물: 첫 HTML 프로필 페이지.
- 복습: HTML이 담당하는 역할과 태그 하나를 설명한다.
- 확장 과제: `header`, `main`, `section`, `footer`로 문서 구조를 개선한다.
- 다음 주차 연결: CSS로 정보의 시각적 위계를 만든다.

## 6주차 — CSS로 읽기 좋은 화면 만들기

- 학습 목표: 선택자와 핵심 속성을 사용해 색상, 글자, 간격, 박스를 꾸민다.
- 핵심 개념: 선택자, 속성·값, 박스 모델, 색 대비, 일관성.
- 교사 설명: 꾸미기보다 읽기 쉬움과 상태 구분이 먼저라는 기준을 제시한다.
- 시연: 5주차 페이지에 클래스와 CSS를 적용하고 일부 속성을 껐다 켠다.
- 학생 실습: 색상 3개 이내, 글꼴 크기 단계, 카드 스타일을 적용한다.
- 실습용 프롬프트: `다음 HTML을 중학생이 읽기 쉬운 카드형 화면으로 꾸밀 CSS를 작성해 줘. 색 대비와 여백을 우선하고 각 선택자가 어느 요소를 바꾸는지 설명해: [HTML]`
- 학생 미션: 모바일 폭에서도 가로 스크롤 없이 읽히도록 개선한다.
- 예상 문제: 선택자 불일치, CSS 연결 실패, 낮은 대비.
- 문제 해결 방법: 파일 경로와 클래스 철자를 확인하고 브라우저 검사 도구로 적용 여부를 본다.
- 결과물: 반응형 프로필 카드.
- 복습: margin과 padding의 차이를 그림으로 표시한다.
- 확장 과제: CSS 변수로 색상과 간격 규칙을 만든다.
- 다음 주차 연결: JavaScript로 화면에 행동을 추가한다.

## 7주차 — JavaScript로 반응하는 페이지 만들기

- 학습 목표: 변수, 이벤트, 함수의 역할을 이해하고 버튼 상호작용을 구현한다.
- 핵심 개념: 값, 변수, 함수, 이벤트, DOM 선택, 상태.
- 교사 설명: “기억하기–행동 묶기–사용자 신호 받기”로 변수·함수·이벤트를 연결한다.
- 시연: 버튼 클릭으로 인사말과 클릭 횟수가 바뀌는 예제를 한 줄씩 실행한다.
- 학생 실습: 응원 문구를 바꾸는 버튼과 횟수 표시를 만든다.
- 실습용 프롬프트: `버튼을 누를 때 문구와 클릭 횟수가 바뀌는 초보자용 JavaScript를 작성해 줘. HTML 연결 위치와 실행 순서를 단계별로 설명해.`
- 학생 미션: 초기화 버튼을 스스로 추가하고 세 가지 동작을 테스트한다.
- 예상 문제: 요소 id 불일치, 스크립트 실행 시점 오류, 문자열·숫자 혼동.
- 문제 해결 방법: 콘솔 오류의 파일·줄 번호를 읽고 값과 자료형을 출력한다.
- 결과물: 상호작용 응원 카드.
- 복습: 클릭부터 화면 변경까지의 흐름을 화살표로 쓴다.
- 확장 과제: 문구 목록에서 무작위로 하나를 선택한다.
- 다음 주차 연결: 조건과 반복으로 퀴즈 로직을 만든다.

## 8주차 — 조건과 반복으로 퀴즈 만들기

- 학습 목표: 조건문, 배열, 반복을 이용해 여러 문항을 처리한다.
- 핵심 개념: Boolean, if/else, 배열, 인덱스, 반복, 점수.
- 교사 설명: 조건은 갈림길, 배열은 순서 있는 보관함이라는 모델로 설명한다.
- 시연: 한 문제 채점 코드를 여러 문제 퀴즈로 확장한다.
- 학생 실습: 3문항 퀴즈와 점수·피드백 화면을 구현한다.
- 실습용 프롬프트: `문제·보기·정답을 배열에 저장하는 3문항 웹 퀴즈 예제를 만들어 줘. 정답 비교와 점수 증가 부분을 초보자에게 설명해.`
- 학생 미션: 틀린 문항만 다시 볼 수 있는 기능을 설계하거나 구현한다.
- 예상 문제: 인덱스 범위 오류, 문자열 정답 비교 오류, 중복 점수.
- 문제 해결 방법: 현재 문항 번호와 값을 콘솔에 출력하고 테스트 순서를 고정한다.
- 결과물: 작동하는 3문항 웹 퀴즈.
- 복습: 조건과 반복이 각각 필요한 위치를 표시한다.
- 확장 과제: 문제 순서를 섞고 최고 점수를 저장한다.
- 다음 주차 연결: 사용자 입력과 데이터를 다루는 미니 프로젝트로 통합한다.

## 9주차 — 웹 기초 미니 프로젝트

- 학습 목표: HTML·CSS·JavaScript를 통합해 작은 문제를 해결하고 발표한다.

## 17주차 — Multi-Agent와 역할 분배

- 학습 목표: 독립 가능한 작업을 구분하고 역할·입력·출력·검수자를 정의한다.
- 핵심 개념: 역할 분리, 병렬 작업, 의존성, 인계, 충돌, 검수.
- 교사 설명: 역할 수가 많다고 좋은 것은 아니며 통합 비용과 책임 소재가 중요함을 설명한다.
- 시연: 퀴즈 프로젝트를 기획, 콘텐츠, 개발, 테스트 역할로 나누고 의존성을 표시한다.
- 학생 실습: 팀 프로젝트의 역할 카드와 인계 규격을 만든다.
- 실습용 프롬프트: `프로젝트 [설명]을 3개 역할로 나눠 줘. 각 역할의 목표, 필요한 입력, 산출물, 완료 조건, 다른 역할과의 의존성을 표로 작성해.`
- 학생 미션: 중복되거나 빠진 책임을 찾아 한 명의 최종 검수자를 정한다.
- 예상 문제: 역할 간 결과 형식이 달라 통합되지 않거나 같은 파일을 동시에 수정한다.
- 문제 해결 방법: 공통 산출물 형식과 파일 담당자를 먼저 정한다.
- 결과물: Multi-Agent 역할표와 인계 계약.
- 복습: 병렬로 가능한 작업과 순서가 필요한 작업을 하나씩 든다.
- 확장 과제: 역할 하나가 실패했을 때 대체 흐름을 설계한다.
- 다음 주차 연결: 전체 AI 개발 워크플로우를 한 번 리허설한다.

## 18주차 — AI 개발 워크플로우 종합 실습

- 학습 목표: 문제 정의부터 테스트·회고까지 전 과정을 작은 프로젝트로 수행한다.
- 핵심 개념: 워크플로우, 작업 보드, 검토 지점, 증거, 완료 정의.
- 교사 설명: 각 단계의 산출물이 다음 단계의 입력이 되는 관계를 강조한다.
- 시연: 30분 제한 미니 앱을 요구사항–구현–테스트–개선 순서로 완주한다.
- 학생 실습: “오늘의 선택 도우미” 같은 소형 앱을 팀별로 완성한다.
- 실습용 프롬프트: `다음 문제를 60분 안에 해결할 최소 웹앱으로 정의해. 계획, 구현 단계, 단계별 테스트, 포기할 기능을 분리해: [문제]`
- 학생 미션: AI 생성 코드 중 한 부분을 설명하고 테스트 증거를 함께 발표한다.
- 예상 문제: 계획에 시간을 과다 사용하거나 마지막에 테스트를 몰아서 한다.
- 문제 해결 방법: 15분 단위 점검과 기능별 즉시 테스트를 적용한다.
- 결과물: 종합 미니 앱, 작업 기록, 테스트 증거.
- 복습: 전체 과정에서 자신이 보완할 단계 하나를 정한다.
- 확장 과제: 다른 팀 요구사항을 받아 개선 제안을 작성한다.
- 다음 주차 연결: 최종 프로젝트 문제를 탐색하고 선택한다.

## 19주차 — 최종 프로젝트: 문제 발견과 제안

- 학습 목표: 실제 사용자의 문제를 관찰하고 실행 가능한 프로젝트 제안서를 작성한다.
- 핵심 개념: 사용자 인터뷰, 문제 근거, 가치, 범위, 윤리·안전.
- 교사 설명: 만들고 싶은 기능보다 누가 어떤 상황에서 겪는 문제인지 먼저 확인하게 한다.
- 시연: 넓은 아이디어를 한 사용자·한 상황·한 핵심 문제로 좁힌다.
- 학생 실습: 아이디어 3개를 문제성·실현성·흥미로 평가해 하나를 선택한다.
- 실습용 프롬프트: `아이디어 [아이디어]에 대해 해결하려는 문제, 사용자, 사용 상황, 가정, 확인 질문을 정리해. 해결책을 확정하지 말고 위험한 가정부터 표시해.`
- 학생 미션: 잠재 사용자 두 명의 피드백 또는 교사가 제공한 사용자 카드로 가정을 검증한다.
- 예상 문제: 너무 큰 문제, 개인 데이터 수집, 기존 서비스 복제.
- 문제 해결 방법: 핵심 사용자와 기능 하나로 줄이고 데이터 최소 수집 원칙을 적용한다.
- 결과물: 프로젝트 제안서와 아이디어 선택 근거.
- 복습: 확인된 사실과 아직 가정인 내용을 구분한다.
- 확장 과제: 대안 해결책 세 가지를 비교한다.
- 다음 주차 연결: 요구사항, 화면, 데이터, 작업 계획을 설계한다.

## 20주차 — 최종 프로젝트: 설계와 계획

- 학습 목표: 사용자 흐름, 화면 구조, 데이터, 완료 조건, 개발 일정을 만든다.
- 핵심 개념: 사용자 흐름, 와이어프레임, 데이터 모델, 작업 우선순위, 위험 관리.
- 교사 설명: 구현 전에 종이 화면을 테스트하면 비용이 줄어드는 이유를 보여준다.
- 시연: 첫 화면에서 목표 달성까지의 흐름과 예외 상황을 연결한다.
- 학생 실습: 핵심 화면 와이어프레임과 3주 개발 보드를 작성한다.
- 실습용 프롬프트: `프로젝트 [설명]의 핵심 사용자 흐름, 필요한 화면, 저장할 데이터, 오류 상태를 정리해. 필수 기능과 이후 기능을 분리하고 각 필수 기능의 완료 조건을 써 줘.`
- 학생 미션: 종이 프로토타입을 친구에게 사용시키고 막힌 지점을 수정한다.
- 예상 문제: 화면 디자인에만 집중하거나 기술 선택이 과도하다.
- 문제 해결 방법: 사용자 목표와 테스트 조건부터 확정하고 익숙한 기술을 우선한다.
- 결과물: 설계서, 와이어프레임, 작업 보드, 테스트 초안.
- 복습: 가장 큰 개발 위험과 대응책을 적는다.
- 확장 과제: 접근성·개인정보·오프라인 대체 흐름을 설계한다.
- 다음 주차 연결: 핵심 기능의 작동하는 첫 버전을 만든다.

## 21주차 — 최종 프로젝트: 핵심 기능 구현

- 학습 목표: 작업을 작은 단위로 구현하고 각 단위의 작동을 확인한다.
- 핵심 개념: 수직 기능 조각, 통합, 상태, 변경 기록, 범위 관리.
- 교사 설명: 화면 전체보다 사용자가 처음부터 끝까지 한 가지를 완료하는 흐름을 우선한다.
- 시연: 요구사항 하나를 선택해 구현 요청, diff 검토, 실행, 테스트를 반복한다.
- 학생 실습: 핵심 사용자 흐름 하나를 완성한다.
- 실습용 프롬프트: `현재 프로젝트와 요구사항을 먼저 확인해. 이번에는 [한 기능]만 구현하고 관련 없는 파일은 바꾸지 마. 완료 후 변경 파일, 작동 방식, 직접 확인할 테스트를 알려 줘.`
- 학생 미션: 생성된 코드의 핵심 함수 또는 흐름을 자신의 말로 설명한다.
- 예상 문제: AI가 범위를 넘어 수정하거나 생성 코드가 기존 기능을 깨뜨린다.
- 문제 해결 방법: 변경 범위를 명시하고 diff와 기존 핵심 테스트를 확인한다.
- 결과물: 핵심 기능이 작동하는 알파 버전.
- 복습: 오늘 완료한 것과 미완료인 것을 구분한다.
- 확장 과제: 반복 코드를 함수 또는 데이터 구조로 정리한다.
- 다음 주차 연결: 전체 기능과 오류 상태를 완성한다.

## 22주차 — 최종 프로젝트: 기능 완성·디버깅

- 학습 목표: 필수 기능을 통합하고 체계적인 디버깅으로 주요 오류를 해결한다.
- 핵심 개념: 통합 테스트, 우선순위, 오류 로그, 원인 분석, 회귀.
- 교사 설명: 치명적·주요·경미 오류를 구분하고 제한 시간에 맞게 처리하는 법을 안내한다.
- 시연: 오류 보고서를 재현 가능한 형태로 바꾸고 하나씩 해결한다.
- 학생 실습: 팀 테스트로 버그를 수집하고 우선순위 상위 오류부터 수정한다.
- 실습용 프롬프트: `오류를 재현하는 단계는 [단계], 기대 결과는 [기대], 실제 결과는 [실제], 콘솔 메시지는 [메시지]야. 원인 가설과 최소 수정안을 제시하고 영향받을 기존 기능도 알려 줘.`
- 학생 미션: 최소 하나의 버그를 재현–수정–회귀 테스트까지 기록한다.
- 예상 문제: 새 기능을 계속 추가하거나 증상만 가린다.
- 문제 해결 방법: 기능 동결선을 정하고 원인 확인 전 대규모 수정을 금지한다.
- 결과물: 필수 기능 베타 버전과 버그 기록.
- 복습: 가장 어려운 버그의 증거와 원인을 설명한다.
- 확장 과제: 예외 상황 처리 또는 성능을 한 가지 개선한다.
- 다음 주차 연결: 실제 사용자 피드백으로 품질을 높인다.

## 23주차 — 최종 프로젝트: 사용자 테스트와 개선

- 학습 목표: 관찰 가능한 사용자 테스트를 진행하고 근거에 따라 개선 우선순위를 정한다.
- 핵심 개념: 사용성 테스트, 관찰, 질문 편향, 심각도, 접근성, 개선 효과.
- 교사 설명: 사용자를 가르치지 않고 행동을 관찰하며 의견과 사실을 구분하는 법을 설명한다.
- 시연: 짧은 테스트 대본으로 과업 성공 여부와 막힌 지점을 기록한다.
- 학생 실습: 최소 두 명에게 핵심 과업을 수행하게 하고 결과를 정리한다.
- 실습용 프롬프트: `다음 사용자 테스트 기록을 성공 여부, 막힌 지점, 심각도, 수정 후보로 정리해. 사용자의 말과 관찰자의 추측을 구분해: [기록]`
- 학생 미션: 가장 영향이 큰 문제 하나를 고치고 같은 과업으로 재시험한다.
- 예상 문제: 사용자를 유도하거나 모든 의견을 기능으로 추가한다.
- 문제 해결 방법: 중립적 대본을 사용하고 목표 달성 방해 정도로 우선순위를 정한다.
- 결과물: 사용자 테스트 보고서와 개선된 출시 후보.
- 복습: 피드백을 수용·보류한 이유를 각각 쓴다.
- 확장 과제: 키보드 조작, 색 대비, 작은 화면을 점검한다.
- 다음 주차 연결: 개발 과정과 결과를 근거 중심으로 발표한다.

## 24주차 — 최종 프로젝트: 발표와 회고

- 학습 목표: 문제, 과정, 결과, 검증, 한계를 논리적으로 발표하고 다음 개선을 계획한다.
- 핵심 개념: 스토리텔링, 데모, 증거, 한계 공개, 회고, 피드백.
- 교사 설명: 기능 나열보다 문제–선택–시행착오–효과가 드러나는 발표 구조를 안내한다.
- 시연: 실패 상황을 대비한 데모 체크리스트와 백업 화면을 준비한다.
- 학생 실습: 5분 발표와 3분 질의응답을 진행하고 동료 피드백을 작성한다.
- 실습용 프롬프트: `프로젝트 정보 [정보]로 5분 발표 개요를 작성해. 문제, 사용자, 핵심 기능, AI와 협업한 방식, 테스트 증거, 실패와 수정, 한계, 다음 단계 순서로 구성해.`
- 학생 미션: AI가 만든 부분과 자신이 검증·수정한 부분을 명확히 구분해 설명한다.
- 예상 문제: 인터넷·API 장애, 설명되지 않는 코드, 성공 사례만 제시.
- 문제 해결 방법: 로컬 데이터나 녹화·스크린샷을 준비하고 실패와 한계를 솔직히 포함한다.
- 결과물: 작동하는 최종 프로젝트, 발표, 과정 포트폴리오, 회고문.
- 복습: 24주 동안 달라진 문제 해결 습관 세 가지를 쓴다.
- 확장 과제: 실제 사용자의 장기 피드백을 받아 다음 버전 로드맵을 만든다.
- 다음 주차 연결: 독립 프로젝트 운영 또는 심화 트랙(백엔드, 데이터, Agent)으로 연결한다.
