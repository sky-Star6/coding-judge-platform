# AI·코딩 시즌제 장기 교육과정 (시즌 1 ~ 시즌 6+)

## 과정 개요

- 대상: 중학생 이상, 코딩 무경험자부터 기초 경험자
- 방식: **4~6주 단위의 시즌제(Season)**로 운영하여 매 시즌마다 완성된 결과물(게임, 도구, 웹앱)을 제작
- 시간: 주 1회, 회당 120분 권장
- 기본 환경: 웹 브라우저, 무료 AI 도구(Google AI Studio 등 카드 등록 없는 무료 서비스), 텍스트 편집기
- 공통 수업 흐름: 도입(10분) → 개념 & 흥미 시연(20분) → 실습 & 미션(50분) → 짝꿍 테스트 & 공유(15분) → 회고 및 정리(5분)
- 핵심 철학: *"AI의 답은 정답지가 아니라 검토하고 개선해야 할 초안이다."*

# 🎮 [시즌 1] AI 스토리 & 비주얼 노벨 크리에이터 (1–6강)

### 1강 — AI는 거짓말쟁이? AI의 원리와 팩트체크 배틀
- 학습 목표: 생성형 AI의 확률적 텍스트 생성 원리를 이해하고, 그럴듯한 거짓말(환각, Hallucination)을 찾아 검증한다.
- 핵심 개념: 생성형 AI(Generative AI), 확률적 다음 단어 예측, 환각(Hallucination), 개인정보 보호(Privacy).
- 교사 설명: AI는 백과사전이 아니라 “다음에 올 가장 그럴듯한 단어를 추측하는 앵무새”임을 재미있는 말잇기 비유로 설명한다.
- 시연: "조선시대 스마트폰 전쟁에 대해 알려줘" 같은 가짜 역사 질문을 던져 AI가 천연덕스럽게 거짓말하는 모습을 함께 관찰한다.
- 학생 실습: **「AI 거짓말 탐지기 챌린지」** — AI에게 엉뚱한 질문을 던져 그럴듯한 헛소리를 유도하고, 진짜 백과사전 검색으로 팩트체크 표를 완성한다.
- 실습용 프롬프트: `중학생에게 설명하듯 [주제]에 대해 재미있게 설명해 줘. 만약 확실하지 않은 사실이 있다면 솔직하게 모른다고 표시해 줘.`
- 학생 미션: AI가 자신 있게 말하지만 완전히 틀린 정보 1개를 찾아내고, 올바른 근거 자료와 함께 수정본을 제출한다.
- 예상 문제: AI의 답변을 의심 없이 100% 믿거나, 학교 이름·전화번호 등 개인정보를 프롬프트에 입력한다.
- 문제 해결 방법: 최소 2개 이상의 검색 결과로 교차 검증하고, 모든 개인정보는 가상의 이름(예: 홍길동)으로 대체한다.
- 결과물: AI 팩트체크 검증 카드 1장.
- 복습: "AI의 답은 정답지가 아니라 초안이다"라는 말을 나만의 언어로 요약한다.
- 다음 강 연결: AI가 헛소리하지 않고 내가 원하는 답을 내놓게 만드는 ‘프롬프트 마법 주문’을 배운다.

### 2강 — 상상을 현실로: 나만의 판타지 캐릭터와 세계관 프롬프트
- 학습 목표: 역할(Role), 맥락(Context), 제약 조건(Constraints), 출력 형식(Format)을 갖춘 고품질 프롬프트를 작성한다.
- 핵심 개념: 프롬프트 엔지니어링(Prompt Engineering), 페르소나(Persona), 명확한 제약 조건, 출력 템플릿.
- 교사 설명: "재밌는 거 써줘"라는 모호한 주문과 "판타지 모험 게임의 드워프 대장장이 대사를 써줘"라는 구체적 주문의 품질 차이를 비교한다.
- 시연: 단순한 "게임 캐릭터 만들어줘" 프롬프트를 [이름/성격/능력치/시그니처 대사/약점]이 포함된 완벽한 프롬프트로 단계별 업그레이드한다.
- 학생 실습: 내가 만들 비주얼 노벨의 **주인공, 동료, 빌런(악당) 캐릭터 시트**를 AI와 함께 창작한다.
- 실습용 프롬프트: `너는 판타지 게임 기획자야. [세계관 키워드]에 어울리는 개성 넘치는 캐릭터 1명을 만들어 줘. 이름, 성격, 특수능력, 약점, 말버릇을 표(Table) 형식으로 정리해.`
- 학생 미션: AI가 생성한 캐릭터 설정 중 마음에 들지 않는 부분 2가지를 프롬프트 수정(재질문)을 통해 원하는 방향으로 고친다.
- 예상 문제: 조건을 한꺼번에 너무 많이 넣어 AI가 일부 지시를 무시한다.
- 문제 해결 방법: 역할 ➔ 세계관 ➔ 캐릭터 속성 순서대로 핵심 조건을 3~4개로 정리하여 전달한다.
- 결과물: 비주얼 노벨 등장인물 프로필 카드 3종 세트.
- 다음 강 연결: 이 캐릭터들이 모험을 떠나는 갈림길 스토리(선택지 분기)를 설계한다.

### 3강 — 갈림길의 모험: 스토리 분기와 선택지 설계
- 학습 목표: 큰 이야기를 '입력-선택-결과'의 작은 단위로 쪼개고, 선택에 따라 엔딩이 바뀌는 분기형 스토리를 설계한다.
- 핵심 개념: 작업 분해(Decomposition), 분기(Branching), 상태(State), 순서도(Flowchart), 게임 오버와 해피 엔딩.
- 교사 설명: 넷플릭스 인터랙티브 영화(밴더스내치)나 게임북처럼, 독자의 선택에 따라 전개가 달라지는 구조를 다이어그램으로 설명한다.
- 시연: "동굴 탐험" 시작 장면 ➔ [왼쪽 길: 함정] / [오른쪽 길: 보물 상자]로 이어지는 3단계 분기 트리를 작성한다.
- 학생 실습: 2강에 만든 캐릭터가 등장하는 **3단계 인터랙티브 스토리 트리(선택지 4개 이상, 멀티 엔딩 2개 이상)**를 구성한다.
- 실습용 프롬프트: `이 캐릭터 [캐릭터 설명]가 [위기 상황]에 처했어. 플레이어가 선택할 수 있는 2가지 행동 [선택 A], [선택 B]를 만들고, 각각의 선택에 따른 다음 전개와 긴장감 넘치는 결말을 작성해 줘.`
- 학생 미션: 짝꿍에게 스토리 선택지를 읽어주고, 짝꿍이 어떤 선택을 하는지 보며 결말이 납득 가능한지 피드백을 받는다.
- 예상 문제: 분기가 너무 복잡해져서 결말을 맺지 못하고 흐지부지된다.
- 문제 해결 방법: "시작 ➔ 1차 선택 ➔ 2차 선택 ➔ 엔딩"의 최대 3단계 깊이로 범위를 한정한다.
- 결과물: 비주얼 노벨 스토리 분기 설계도(시나리오 트리).
- 다음 강 연결: 스토리에 버그나 모순이 없는지 AI와 함께 밸런스 패치(디버깅)를 진행한다.

### 4강 — AI와 함께하는 밸런스 패치: 스토리 검증과 개선
- 학습 목표: 스토리의 개연성, 논리적 오류, 난이도를 비판적으로 평가하고 AI 피드백을 활용해 완성도를 높인다.
- 핵심 개념: 품질 검증(Quality Assurance), 논리적 모순(Plot Hole), 피드백 공식(위치-이유-대안), 버전 관리(v1/v2).
- 교사 설명: 게임 회사의 게임 기획자와 QA(품질보증) 팀이 스토리를 어떻게 테스트하고 밸런스를 맞추는지 소개한다.
- 시연: "열쇠를 얻지 않았는데 문이 열리는 모순"을 찾아내고, AI에게 논리적 인과관계를 수정하도록 요청하는 과정을 보여준다.
- 학생 실습: 3강에 작성한 스토리 분기를 AI에게 평가받고, 모순점 2개와 더 흥미진진한 반전 요소를 보완한다.
- 실습용 프롬프트: `다음 게임 스토리 트리를 읽고 1) 논리적으로 앞뒤가 안 맞는 부분, 2) 너무 싱거운 선택지를 찾아내 줘. 그리고 더 극적인 반전을 줄 수 있는 수정안 2가지를 제안해 줘: [스토리]`
- 학생 미션: AI가 제안한 개선안 중 1개는 채택하고 1개는 거절한 뒤, 그 이유를 기록하여 최종 스토리 v2를 확정한다.
- 결과물: 완성된 비주얼 노벨 대본 v2 및 검증 기록.
- 다음 강 연결: 이제 이 멋진 스토리를 화면에 띄우기 위해 웹의 뼈대(HTML)를 조립한다!

### 5강 — 게임 화면의 뼈대 만들기: HTML로 대사창과 선택지 조립
- 학습 목표: HTML 태그와 요소(Element)를 이해하고, 비주얼 노벨 게임에 필요한 대사창, 캐릭터 영역, 선택지 버튼을 작성한다.
- 핵심 개념: HTML 문서 구조, 태그와 속성, 제목(`h1`), 문단(`p`), 버튼(`button`), 컨테이너(`div`), 이미지(`img`).
- 교사 설명: HTML은 게임의 뼈대이자 무대 장치다. 텍스트 박스, 캐릭터 일러스트 자리, 클릭할 버튼의 자리를 배치하는 법을 배운다.
- 시연: 빈 메모장에서 `index.html`을 만들고, 태그를 추가할 때마다 브라우저를 새로고침하며 화면이 생겨나는 과정을 보여준다.
- 학생 실습: AI에게 HTML 기초 뼈대를 요청하고, 내 스토리에 맞게 제목, 대사, 선택지 버튼 2개를 직접 코드로 조립한다.
- 실습용 프롬프트: `초보자용 비주얼 노벨 게임의 한 장면을 만들고 싶어. 화면 상단엔 배경/캐릭터 영역(div), 중간엔 대사창(p), 하단엔 선택지 버튼 2개(button)가 있는 깔끔한 HTML 뼈대 코드를 작성해 줘. 주석으로 각 태그의 역할을 설명해 줘.`
- 학생 미션: 생성된 코드에서 버튼 글자를 내 스토리의 선택지 문구로 바꾸고, 버튼을 눌러도 화면이 깨지지 않는지 확인한다.
- 예상 문제: 태그를 닫지 않거나(`</p>` 누락), 한글 인코딩이 깨지는 문제.
- 문제 해결 방법: 브라우저 개발자 도구(F12)를 열어 빨간 오류를 확인하고 `<meta charset="UTF-8">` 설정을 점검한다.
- 결과물: 첫 HTML 비주얼 노벨 게임 화면 뼈대.
- 다음 강 연결: CSS로 마법 같은 판타지 분위기와 멋진 버튼 스타일을 입힌다!

### 6강 — 판타지 감성 입히기: CSS 스타일링 & 시즌 1 쇼케이스
- 학습 목표: CSS 선택자와 스타일 속성을 활용해 어두운 던전/화려한 궁전 분위기를 연출하고, 시즌 1 완성작을 짝꿍과 플레이한다.
- 핵심 개념: CSS 선택자, 색상과 배경, 박스 모델(Padding/Margin), 폰트 스타일, 버튼 호버(Hover) 효과, 반응형 기본.
- 교사 설명: 흑백 글자뿐이던 무대에 조명을 켜고 화려한 옷을 입히는 것이 CSS다. 어두운 테마와 화려한 버튼 효과를 실습한다.
- 시연: 5강 HTML 파일에 `<style>` 태그를 넣고, 배경색을 밤하늘색(`#0f172a`)으로 바꾸고 버튼에 반짝이는 마우스 오버 효과를 입힌다.
- 학생 실습: AI에게 내 세계관(사이버펑크, 중세 판타지, 공포 방탈출 등)에 어울리는 CSS 스타일을 요청하여 웹 게임 화면을 완성한다.
- 실습용 프롬프트: `이 HTML 게임 화면을 [내가 정한 분위기: 예 - 신비로운 마법 도서관] 분위기로 꾸밀 CSS 코드를 작성해 줘. 배경색, 읽기 쉬운 글자색, 마우스를 올리면 빛나는 버튼 효과를 포함해 줘: [내 HTML 코드]`
- 학생 미션: **「시즌 1 비주얼 노벨 쇼케이스」** — 내 완성작을 옆 짝꿍에게 보여주고, 짝꿍이 직접 선택지를 클릭하며 엔딩까지 플레이하게 한다.
- 결과물: **[시즌 1 완성작] 작동하는 나만의 인터랙티브 웹 비주얼 노벨 v1.0**.
- 다음 시즌 연결: 시즌 2에서는 JavaScript를 배워 선택지를 누르면 페이지 새로고침 없이 다음 장면으로 술술 넘어가는 진짜 게임 로직과 미니 아케이드 게임을 만든다!

## 7강 — JavaScript로 반응하는 페이지 만들기

## 8강 — 조건과 반복으로 퀴즈 만들기

- 학습 목표: 조건문, 배열, 반복을 이용해 여러 문항을 처리한다.

- 시연: 한 문제 채점 코드를 여러 문제 퀴즈로 확장한다.
- 학생 실습: 3문항 퀴즈와 점수·피드백 화면을 구현한다.

- 학생 미션: 틀린 문항만 다시 볼 수 있는 기능을 설계하거나 구현한다.

- 결과물: 작동하는 3문항 웹 퀴즈.
- 복습: 조건과 반복이 각각 필요한 위치를 표시한다.
- 확장 과제: 문제 순서를 섞고 최고 점수를 저장한다.
- 다음 강 연결: 사용자 입력과 데이터를 다루는 미니 프로젝트로 통합한다.

## 12강 — AI와 디버깅하기

- 시연: 의도적으로 망가진 퀴즈를 실행하고 관찰–가설–수정–재시험 기록을 남긴다.
- 학생 실습: 세 종류의 버그가 있는 샘플을 팀별로 고친다.
- 실습용 프롬프트: `기대 결과는 [기대], 실제 결과는 [실제], 오류 메시지는 [메시지]야. 바로 전체 코드를 다시 쓰지 말고 가능한 원인 3개와 확인 순서를 제시해.`

- 결과물: 디버깅 로그와 수정된 샘플.
- 복습: 좋은 오류 보고의 네 요소를 적는다.
- 확장 과제: `console.log` 없이 개발자 도구의 중단점을 사용해 본다.

- 학습 목표: 일반 챗봇과 Agent의 차이를 설명하고 목표–계획–도구–검증 루프를 설계한다.
- 핵심 개념: Agent, 목표, 상태, 도구, 관찰, 반복, 종료 조건, Hermes의 관리 역할.
- 교사 설명: Hermes가 직접 모든 산출물을 만드는 존재가 아니라 작업을 설계·관리하는 역할임을 구분한다.
- 시연: “학습 퀴즈 만들기”를 계획, 자료 확인, 생성, 검토, 완료 판단 흐름으로 그린다.
- 학생 실습: 사람이 수행하는 종이 기반 에이전트 시뮬레이션으로 단계와 상태를 기록한다.
- 실습용 프롬프트: `목표 [목표]를 달성하는 에이전트 흐름을 계획→도구 사용→관찰→검증→종료로 설계해. 각 단계에서 사람이 확인할 항목도 써 줘.`
- 학생 미션: 무한 반복 또는 잘못된 도구 사용 위험을 찾아 종료 조건을 보완한다.
- 예상 문제: Agent를 단순 자동 답변으로 이해하거나 모든 권한을 허용한다.
- 문제 해결 방법: 행동 전 승인 지점과 명확한 종료 조건을 흐름도에 표시한다.
- 결과물: 에이전트 작업 흐름도와 안전 규칙.
- 복습: 챗봇과 Agent의 차이를 두 문장으로 쓴다.
- 확장 과제: 실패·재시도·사람 검토 분기를 추가한다.
- 다음 강 연결: 여러 Agent가 역할을 나누는 구조를 설계한다.

## 17강 — Multi-Agent와 역할 분배

- 시연: 퀴즈 프로젝트를 기획, 콘텐츠, 개발, 테스트 역할로 나누고 의존성을 표시한다.
- 학생 실습: 팀 프로젝트의 역할 카드와 인계 규격을 만든다.
- 실습용 프롬프트: `프로젝트 [설명]을 3개 역할로 나눠 줘. 각 역할의 목표, 필요한 입력, 산출물, 완료 조건, 다른 역할과의 의존성을 표로 작성해.`
- 학생 미션: 중복되거나 빠진 책임을 찾아 한 명의 최종 검수자를 정한다.
- 예상 문제: 역할 간 결과 형식이 달라 통합되지 않거나 같은 파일을 동시에 수정한다.
- 문제 해결 방법: 공통 산출물 형식과 파일 담당자를 먼저 정한다.
- 결과물: Multi-Agent 역할표와 인계 계약.
- 복습: 병렬로 가능한 작업과 순서가 필요한 작업을 하나씩 든다.
- 확장 과제: 역할 하나가 실패했을 때 대체 흐름을 설계한다.
- 다음 강 연결: 전체 AI 개발 워크플로우를 한 번 리허설한다.

- 복습: 전체 과정에서 자신이 보완할 단계 하나를 정한다.

- 복습: 오늘 완료한 것과 미완료인 것을 구분한다.

## 24강 — 최종 프로젝트: 발표와 회고
