QUEST 01 쿼리 스트링 URL 조립
NEIS API & URLSearchParams

QUEST 01. 나이스(NEIS) 급식 오픈 API URL과 필수 쿼리 스트링 조합 함수 만들기

교육청 코드, 학교 코드, 조회 날짜(YYYYMMDD)를 인자로 받아 표준 규격의 완전한 나이스 API 호출 URL을 안전하게 조립하는 파이프라인 함수를 작성합니다.

실전 함정 상황: 문자열 더하기(+)로 URL을 조합하다가 '&'나 '='가 누락되어 서버로부터 'INVALID_REQUEST' 에러를 받는 흔한 실수!
복사해서 AI에게 보낼 프롬프트 (클릭 시 자동 복사)
[역할] 너는 공공데이터 포털과 나이스(NEIS) 교육정보 개방 포털 API에 능숙한 시니어 백엔드 엔지니어이자 웹 코치야. [상황 및 요구사항] 학생이 나이스 급식 식단 정보 API('https://open.neis.go.kr/hub/mealServiceDietInfo')를 호출하려고 해. 필수 쿼리 파라미터는 다음과 같아: - Type: 'json' - pIndex: 1 - pSize: 5 - ATPT_OFCDC_SC_CODE: 교육청 코드 (예: 서울 'B10') - SD_SCHUL_CODE: 표준 학교 코드 (예: '7010578') - MLSV_YMD: 급식 일자 8자리 (예: '20261109') [요청 사항] 1. URLSearchParams 객체를 사용하여 위 파라미터들을 인코딩 누락 없이 안전하게 하나의 완성된 URL 문자열로 조합하는 buildNeisMealUrl(officeCode, schoolCode, ymd) 함수를 작성해 줘. 2. 왜 단순 문자열 더하기('url?a=' + a)보다 URLSearchParams를 사용하는 것이 실무 표준인지 주니어 개발자의 눈높이에서 설명해 줘. 3. 매 줄마다 초보 학생을 위한 친절한 한국어 주석을 달아줘.
AI 소환 마법 반응

URLSearchParams 규격을 적용해 파라미터 누락과 오타 위험을 0%로 줄이는 현대적 URL 빌더 코드를 소환합니다!

💡 컴퓨터 과학의 비밀

URLSearchParams는 파라미터 값에 특수문자나 한글이 포함되어도 자동으로 안전한 퍼센트 인코딩을 적용해 주는 브라우저 표준 Web API입니다.

QUEST 02 문자열 정제 & 전처리
Regex String Cleaning

QUEST 02. <br/> 태그와 알레르기 번호 (1.5.6)를 깨끗하게 날리는 정규표현식(Regex) 문자열 정제술

나이스 API가 전송한 원시 텍스트 "친환경 흑미밥<br/>수제 치즈 돈가스(1.2.5.6.10.)"를 파싱해 괄호 속 번호는 따로 분리하고 깨끗한 반찬 배열로 변환하는 정제 함수입니다.

실전 함정 상황: 정제하지 않고 그냥 innerHTML로 넣으면 번호가 덕지덕지 붙어 식판 UI가 엉망이 되고, XSS 보안 취약점 위험까지 발생합니다!
복사해서 AI에게 보낼 프롬프트 (클릭 시 자동 복사)
[역할] 너는 텍스트 처리와 정규표현식(Regular Expression)을 가르치는 데이터 사이언스 강사야. [문제 상황] 교육청 급식 API의 DDISH_NM 속성에는 다음과 같은 지저분한 문자열이 들어있어: '친환경 흑미밥
쇠고기 맑은 무국(5.6.16.)
수제 치즈 돈가스(1.2.5.6.10.)
양배추 샐러드 & 깍두기(9.)' [해결 요청] 1. 정규표현식을 사용해
태그로 각 요리를 쪼개어 배열로 만드는 cleanMealString(rawString) 함수를 작성해 줘. 2. 반찬 이름 뒤에 붙은 '(1.2.5.6.)' 같은 알레르기 번호를 괄호째 정규식(/\([0-9.]+\)/g)으로 제거해 순수한 음식 이름만 남기는 정제 로직을 포함해 줘. 3. 반대로 추출한 알레르기 번호 목록([1, 2, 5, 6, 10])을 별도 배열로 보존하는 방법도 함께 알려줘. 4. 초등학생도 정규식의 기호(., +, \)를 이해할 수 있는 친절한 주석을 달아줘.
AI 소환 마법 반응

복잡한 공공데이터 텍스트를 마법처럼 한 줄의 정규식으로 잘라내어 반찬과 알레르기 정보로 깔끔히 분류하는 정제 코드를 완성합니다!

💡 컴퓨터 과학의 비밀

정규표현식(Regex)은 텍스트 패턴을 찾아내는 초고속 언어입니다. 실무 데이터 파이프라인에서 데이터 정제 시간의 80%가 정규표현식으로 처리됩니다.

QUEST 03 주말 & 휴일 예외 가드
Empty Data & INFO-200 Guard

QUEST 03. "주말이라 급식이 없어요!" — 데이터가 비어 있을 때(INFO-200) 예외 방어 카드 구현

토요일이나 일요일, 여름방학 등 급식이 없는 날짜를 조회했을 때 나이스 API가 던지는 INFO-200(해당 일자에 데이터가 없습니다) 응답을 감지해 친절한 휴일 식판 화면을 띄웁니다.

실전 함정 상황: 데이터가 당연히 있을 것이라 믿고 `data.mealServiceDietInfo[1].row[0]`에 바로 접근하면 'TypeError: Cannot read properties of undefined'로 앱이 다운됩니다!
복사해서 AI에게 보낼 프롬프트 (클릭 시 자동 복사)
[역할] 너는 프론트엔드 오류 방어와 널 세이프티(Null-Safety)를 연구하는 소프트웨어 아키텍트야. [상황] 학생이 주말 날짜로 나이스 급식 API를 호출했더니, data.mealServiceDietInfo 배열이 존재하지 않고 { RESULT: { CODE: 'INFO-200', MESSAGE: '해당하는 데이터가 없습니다.' } } 객체만 반환되어 스크립트 오류가 발생했습니다. [요청 사항] 1. 옵셔널 체이닝(?.)과 조건문 분기를 활용해 급식 데이터 row가 존재하는지 안전하게 검증하는 parseMealResponse(data) 함수를 작성해 줘. 2. 데이터가 정상인 경우 정제된 식단 객체를 반환하고, 주말/방학으로 데이터가 없을 때는 { isHoliday: true, message: '오늘은 급식이 없는 즐거운 휴일입니다! 🏖️' }를 안전하게 반환하도록 처리해 줘. 3. 왜 외부 API 데이터를 다룰 때 '옵셔널 체이닝(?.)'이 실무 필수 기술인지 2문장으로 요약해 줘.
AI 소환 마법 반응

휴일과 방학에도 절대 흰 화면 멈춤이 발생하지 않는 무결점 옵셔널 체이닝 예외 방어 함수를 완성합니다!

💡 컴퓨터 과학의 비밀

옵셔널 체이닝(?.)은 중간 객체가 null이나 undefined여도 런타임 에러를 던지지 않고 안전하게 undefined를 반환하여 프로그램 강제 종료를 막습니다.

QUEST 04 알레르기 안심 필터
Allergy Warning Badge

QUEST 04. 내 알레르기 유발 번호(난류 1번, 우유 2번)를 감지해 빨간 경고 뱃지를 다는 안전 필터 로직

사용자가 설정한 알레르기 유발 식품(예: 1번 난류, 2번 우유, 5번 대두)이 포함된 반찬 카드에 빨간 테두리와 경고 뱃지를 띄워 건강을 지켜주는 안심 필터를 구축합니다.

실전 함정 상황: 알레르기 번호 1번(난류)을 찾을 때 단순 문자열 포함('1')으로 검사하면 '10번(돼지고기)'이나 '15번'까지 1번으로 오인 감지되는 버그 발생!
복사해서 AI에게 보낼 프롬프트 (클릭 시 자동 복사)
[역할] 너는 에듀테크 헬스케어 및 환자 안전 UX를 설계하는 프론트엔드 수석 개발자야. [나이스 알레르기 표준 번호표] 1: 난류(계란), 2: 우유, 3: 메밀, 4: 땅콩, 5: 대두, 6: 밀, 7: 고등어, 8: 게, 9: 새우, 10: 돼지고기, 11: 복숭아, 12: 토마토, 13: 아황산염, 14: 호두, 15: 닭고기, 16: 쇠고기, 17: 오징어, 18: 조개류 [요구사항] 1. 학생의 알레르기 유발 번호 배열(예: [1, 2] -> 계란, 우유 알레르기 보유)과 반찬의 알레르기 정보 문자열(예: '치즈 돈가스(1.2.5.6.10.)')을 비교하는 checkAllergyRisk(dishString, userAllergies) 함수를 작성해 줘. 2. '10번'이나 '15번'을 1번으로 잘못 인식하지 않도록 정확하게 번호 단위로 분리(split('.'))하여 일치 여부를 판별하는 완벽한 배열 비교 로직을 작성해 줘. 3. 알레르기 위험이 발견되었을 때 반환할 결과 객체({ hasRisk: true, matchedAllergies: ['난류', '우유'] })와 화면에 띄울 UI 뱃지 예시를 포함해 줘.

QUEST 05 주간 식단표 배치 루프
Date Range Batch Query

QUEST 05. 이번 주 월~금 5일치 급식 데이터를 한 번에 가져와 주간 식단표로 묶어주는 날짜 범위 쿼리술

하루치만 가져오는 것이 아니라, `MLSV_FROM_YMD=20261109&MLSV_TO_YMD=20261113` 범위 쿼리를 활용해 월요일부터 금요일까지 5일치 식단을 한 번에 받아와 5일 달력 식판으로 펼치는 고급 API 기술입니다.

실전 함정 상황: fetch를 for문으로 5번 반복 호출하면 서버에 불필요한 트래픽 5배를 유발하고 응답 순서가 뒤죽박죽 섞여 월요일과 금요일이 바뀌는 대참사 발생!
복사해서 AI에게 보낼 프롬프트 (클릭 시 자동 복사)
[역할] 너는 대규모 트래픽 최적화와 배치(Batch) API 통신을 전담하는 시니어 웹 아키텍트야. [상황 및 요구사항] 학생이 월요일부터 금요일까지 5일치 학교 식단을 한 번에 조회하여 '주간 급식표'를 만들려고 해. 나이스 API는 MLSV_FROM_YMD와 MLSV_TO_YMD 쿼리 파라미터로 기간 조회를 지원해. [요청 사항] 1. 불필요하게 fetch를 5번 호출하지 않고, 단 1번의 API 호출로 이번 주 5일치 급식 배열을 통째로 받아오는 fetchWeeklyMeals(schoolCode, fromDate, toDate) 함수를 작성해 줘. 2. 받아온 배열을 요일별(월, 화, 수, 목, 금) 키로 묶어주는 자바스크립트 객체 매핑 로직을 작성해 줘. 3. 왜 여러 번의 네트워크 호출(N+1 Query)보다 단일 기간 쿼리가 성능과 배터리 절약 측면에서 우수한지 초보자를 위한 비유로 2줄 요약해 줘.
AI 소환 마법 반응

단 한 번의 네트워크 요청으로 5일치 식단을 완벽하게 요일별로 그룹핑하는 고효율 배치 파이프라인 코드를 소환합니다!

💡 컴퓨터 과학의 비밀

네트워크 요청은 매번 TCP/TLS 핸드셰이크 왕복 시간이 듭니다. 기간 쿼리로 1번에 묶어 가져오면 데이터 전송 속도가 최대 5배 빨라집니다.
