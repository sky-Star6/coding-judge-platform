Stage 1: 미션 브리핑 (아침 등굣길, 현관문 앞 5분의 고민! 🚪)

날씨를 몰라 비를 맞거나 감기에 걸리지 않도록 지켜주는 생활 밀착형 도구
"날씨 앱을 켜면 왜 온도 숫자만 덩그러니 있을까?"

아이들에게 진짜 필요한 건 "14도"라는 숫자보다 "오늘은 아침저녁 쌀쌀하니 가디건을 걸치고, 오후에 소나기가 오니 접이식 우산을 챙겨!"라는 친절한 조언입니다. 우리는 데이터를 그냥 보여주는 데서 멈추지 않고, 데이터를 분석해 **진짜 실생활의 행동 가이드**를 만들어냅니다.

이번 퀘스트의 4대 성공 루브릭 (성공 판정 기준)

1. 기상청 관측 데이터 연동

기상청 초단기 예보 API 규격에 맞추어 기온(T1H), 강수형태(PTY), 하늘상태(SKY) 패킷을 수신합니다.

2. 기온별 5단계 의류 알고리즘

임계값(4℃, 12℃, 20℃, 28℃)에 따라 롱패딩부터 반팔까지 최적의 상의·하의·외투를 판정합니다.

3. 강수 조건부 우산 알림

비, 눈, 소나기 또는 강수확률 60% 이상일 때 '노란 우산 챙기기' 경보 뱃지를 조건부 렌더링합니다.

4. 날씨 반응형 테마 UI

맑음(하늘색), 비(남색), 눈(청록색), 폭염(주황색) 날씨 상태에 따라 배경색과 아이콘이 카멜레온처럼 변합니다.

Stage 2: 핵심 원리 (하늘의 숫자 암호와 조건부 알고리즘)

기상청이 보낸 영문 약자 암호를 해석하고, 의류 추천 로직을 짜는 비법

1. 기상청 슈퍼컴퓨터가 보낸 4대 숫자 암호

기상청 서버에서 날아온 데이터는 "비가 와요"라고 한글로 적혀있지 않고, 짧은 영문 약자와 숫자로 인코딩되어 있습니다. 이 4가지 암호만 풀면 날씨 마스터가 될 수 있어요!

T1H / TMP 기온 (Temperature) 현재 기온 (섭씨 ℃)
PTY 강수 형태 (Type) 0:없음, 1:비, 3:눈
SKY 하늘 상태 (Sky) 1:맑음, 3:구름, 4:흐림
REH 습도 (Humidity) 공기 속 수분 비율 (%)

2. 기온 임계값(Threshold)에 따른 옷차림 분기 공식

컴퓨터에게 "오늘 기온이 28℃ 이상이면 반팔을 추천하고, 4℃ 이하면 롱패딩을 추천해!"라고 가르치는 조건문(if ... else if) 구조입니다.

// 기온(temp)에 따른 5단계 의류 추천 분기표
if (temp >= 28) { outfit = '민소매, 반팔 티셔츠, 반바지 🩳'; }
else if (temp >= 20) { outfit = '얇은 셔츠, 7부 바지, 면바지 👕'; }
else if (temp >= 12) { outfit = '가디건, 바람막이, 청바지 🧥'; }
else if (temp >= 5) { outfit = '코트, 기모 후드티, 경량패딩 🧤'; }
else { outfit = '롱패딩, 두꺼운 코트, 목도리 🧣'; }

3. 비 오면 자동으로 켜지는 노란 우산 신호등

강수 형태 코드(PTY > 0)가 비나 눈을 가리키면, 화면에 노란 우산 필수 지참! 경고 뱃지를 띄웁니다. 이것이 바로 상태에 따라 화면이 바뀌는 **조건부 렌더링(Conditional Rendering)**입니다.

지리정보/수학

5. 데이터 정규화 영문: Data Normalization (Unit & Format Conversion)
데이터 가공
🧸 어린이 비유: "'28.4', '28도', '28℃'처럼 제각각인 글자들을 모두 모아 예쁜 숫자 '28'로 단정하게 통일해주는 데이터 다림질!"

🎓 개발자 공식 정의: 다양한 소스나 형식으로 수집된 이종(Heterogeneous) 데이터를 일관된 기준 단위(섭씨, %, mm 등)와 정형화된 데이터 타입(Float, Integer)으로 변환하여 시스템 호환성을 높이는 전처리 표준화 작업입니다.

6. 상태 기반 테마 영문: State-Driven UI (Dynamic Theme & Styling)
디자인/인터랙션

🎓 개발자 공식 정의: 애플리케이션의 내부 상태(State) 값의 변화에 즉각 반응하여 배경색, 테마 클래스, 아이콘 세트 등 시각적 룩앤필(Look and Feel)을 동적으로 재계산하고 반영하는 인터페이스 설계 패턴입니다.
