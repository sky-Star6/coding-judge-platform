QUEST 01 기상청 격자 좌표 & 파라미터 빌더
초급 실전 레벨 ★☆☆

기상청 초단기실황 API 호출용 격자 좌표(nx, ny)와 발표 시간 자동 조합기 구현

위도·경도가 아닌 기상청 고유의 격자 정수 좌표(nx, ny)와 현재 시각 기준의 발표일자(base_date), 발표시각(base_time)을 안전하게 조합해 요청 URL을 완성하는 함수를 작성합니다.

실전 함정: GPS 위경도(37.56, 126.97)를 기상청 API에 그대로 던지거나 40분 정각 전 이전 시간대를 계산하지 못하면 400 Bad Request가 발생합니다!
실전 AI 프롬프트 (원클릭 복사)
[역할] 너는 공공데이터 포털과 기상청 오픈 API 연동을 담당하는 시니어 백엔드 엔지니어이자 웹 코치야. [상황 및 요구사항] 기상청 초단기실황 API('http://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtNcst')를 호출하려고 해. 기상청은 30분 단위로 데이터를 생성하며, 매시 40분 이후에 직전 정시 데이터가 최종 확정돼. [요청 사항] 1. URLSearchParams를 사용해 serviceKey, pageNo=1, numOfRows=10, dataType='JSON', base_date, base_time, nx, ny 파라미터를 안전하게 조합하는 buildWeatherApiUrl(nx, ny) 함수를 작성해 줘. 2. 현재 시각이 40분 이전이면 1시간 전 발표 시각으로 자동 롤백하는 안전한 base_time 계산 로직을 포함해 줘. 3. 왜 기상청은 구글 지도 같은 GPS 위도/경도가 아니라 정수 격자 좌표(nx, ny)를 요구하는지 설명해 줘. 4. 초등학생 및 입문자도 각 줄의 목적을 이해할 수 있도록 매 줄마다 상세한 한국어 주석을 달아줘.
✨ AI 충격 반응 & 소환 마법

정각 직후 데이터 누락을 방지하는 40분 롤백 알고리즘과 완벽한 URLSearchParams 파이프라인을 단 3초 만에 소환합니다!

💡 컴퓨터 과학 비밀 해설

기상청은 람베르트 정각원추 투영법(Lambert Conformal Conic)으로 한반도를 5km 격자망으로 나눈 정수 좌표계(nx, ny)를 사용해 계산량을 획기적으로 줄입니다.

QUEST 02 기상 코드(T1H, PTY, REH) 정규화
데이터 정제 & 파싱 ★★☆

배열로 흩어진 기상청 원시 항목(item)들을 단일 날씨 상태 객체로 변환하는 정규화 함수

기상청 API가 보낸 복잡한 배열 형태의 원시 데이터에서 카테고리별 키값(T1H: 기온, PTY: 강수형태, REH: 습도)을 추출해 깔끔한 자바스크립트 객체로 묶어내는 정규화 파서를 구현합니다.

실전 함정: obsrValue가 문자열 "24.2"로 전송되는데, 숫자 변환 없이 더하면 "24.2" + 5 = "24.25"라는 엉터리 기온이 계산됩니다!
실전 AI 프롬프트 (원클릭 복사)
[역할] 너는 공공데이터 JSON 파싱과 데이터 정규화(Normalization) 전문가야. [문제 상황] 기상청 API 응답 json.response.body.items.item은 다음과 같은 배열 형태야: [ { "category": "T1H", "obsrValue": "24.2" }, { "category": "PTY", "obsrValue": "0" }, { "category": "REH", "obsrValue": "45" }, { "category": "WSD", "obsrValue": "2.1" } ] [해결 요청] 1. 위 배열을 .reduce() 또는 순회문으로 탐색해 { temperature: 24.2, rainType: 0, humidity: 45, windSpeed: 2.1 } 단일 객체로 정규화하는 parseWeatherItems(itemArray) 함수를 작성해 줘. 2. 문자열 obsrValue를 parseFloat/parseInt를 사용해 안전한 숫자로 변환하고 NaN 결측치를 감지해 Fallback 기본값을 지정할 것. 3. 데이터 정규화가 프론트엔드 UI 렌더링 코드의 복잡도를 어떻게 70% 이상 낮춰주는지 설명해 줘. 4. 초보자도 쉽게 읽을 수 있도록 친절한 한국어 주석을 달아줘.
✨ AI 충격 반응 & 소환 마법

지저분한 배열 항목을 단 한 번의 순회로 깨끗한 수치 상태 모델로 압축해 런타임 버그를 차단합니다!

데이터 정규화(Normalization)는 외부 서버의 제각각인 규격을 애플리케이션 표준 모델로 일원화해 유지보수성을 극대화하는 기법입니다.

QUEST 03 기온별 5단계 맞춤 의류 알고리즘
조건 분기 알고리즘 ★★★

임계값(28℃, 20℃, 12℃, 5℃)에 따른 상·하의·외투 5단계 판정 알고리즘

기온에 따라 28℃ 이상(한여름), 20~27℃(초여름/봄가을), 12~19℃(환절기), 5~11℃(늦가을), 4℃ 이하(한겨울)의 5개 구간을 한치의 오차 없이 판정하는 추천 엔진을 작성합니다.

실전 함정: 조건문에서 등호(>=)나 부등호 범위를 잘못 적으면 20도에서 두 조건이 동시에 걸리거나 추천이 증발합니다!
실전 AI 프롬프트 (원클릭 복사)
[역할] 너는 패션 테크 알고리즘과 인터랙션 설계를 연구하는 프론트엔드 엔지니어 개발자야. [요구사항] 기온(temperature)을 전달받아 사용자에게 오늘의 최적 의류를 추천하는 getOutfitRecommendation(temp) 함수를 작성하려고 해. [해결 요청] 1. 다음 5단계 임계값에 따라 { top, bottom, outer, advice } 객체를 완벽히 반환할 것: - 28℃ 이상: 민소매/반팔, 반바지, 선글라스, "폭염 주의! 린넨 소재 옷 추천" - 20℃ ~ 27℃: 얇은 긴팔/반팔, 면바지/슬랙스, 얇은 가디건, "쾌적하고 산뜻한 날씨" - 12℃ ~ 19℃: 셔츠/맨투맨, 청바지, 가디건/바람막이, "아침저녁 쌀쌀한 환절기" - 5℃ ~ 11℃: 기모 후드티, 두꺼운 바지, 트렌치코트/경량패딩, "쌀쌀하니 외투 필수" - 4℃ 이하: 두꺼운 니트, 방한 기모바지, 롱패딩/목도리/장갑, "한파 경보! 완전 무장" 2. 경계값(28, 20, 12, 5)에서 if-else if 구조가 겹침 없이 정확하게 동작하도록 작성할 것. 3. 매 줄마다 초보 학생이 이해할 수 있도록 친절한 한국어 주석을 달아줘.
✨ AI 충격 반응 & 소환 마법

날씨 숫자 하나만 주면 머리부터 발끝까지 완벽한 패션을 제안하는 스마트 코디네이터 로직을 완성합니다!

임계값 분기(Threshold Branching)는 연속적인 아날로그 물리량을 이산적인 의사결정 카테고리로 나누는 규칙 기반 인공지능(Rule-based AI)의 기초입니다.

QUEST 04 강수 형태(PTY) 우산 조건부 렌더링
조건부 UI & 반응형 테마 ★★☆

비·눈 감지 시 통통 튀는 노란 우산 알림과 날씨 상태별 배경 테마 카멜레온 전환

강수형태(PTY > 0)일 때 우산 챙기기 알림 뱃지를 통통 튀는 애니메이션과 함께 띄우고, 맑음·비·눈·폭염에 맞춰 배경 그라데이션을 즉시 전환하는 인터랙션 코드를 작성합니다.

실전 함정: 날씨가 맑음으로 바뀌었을 때 우산 뱃지를 다시 숨기지 않으면 하루 종일 우산을 챙기라는 버그가 남습니다!
실전 AI 프롬프트 (원클릭 복사)
[역할] 너는 상태 기반 UI(State-driven UI)와 동적 테마 디자인 시스템 전문가야. [상황] 사용자 화면의 #umbrella-alert-badge는 평소엔 hidden 상태여야 해. 비(PTY=1), 진눈깨비(PTY=2), 눈(PTY=3), 소나기(PTY=4)일 때만 통통 튀는 애니메이션(animate-bounce)과 함께 화면에 나타나야 해. [요청 사항] 1. weatherData.rainType > 0 여부에 따라 classList.remove('hidden') / classList.add('hidden')을 안전하게 토글하는 updateUmbrellaAlert(rainType) 함수를 작성해 줘. 2. 맑음(하늘색 그라데이션), 비(남색/파란색), 눈(청록색), 폭염(주황색/붉은색) 4가지 상태에 맞추어 #weather-banner-box의 Tailwind CSS 배경 클래스를 교체하는 renderWeatherTheme(temp, rainType) 함수를 구현해 줘. 3. DOM 요소가 없을 때 에러가 나지 않도록 널 가드(Null Guard)를 적용해 줘. 4. 초등학생도 이해할 수 있도록 친절한 한국어 주석을 달아줘.

QUEST 05 결측치(-999) 방어 & 슬라이더 양방향 연동
결측치 처리 & 이벤트 연동 ★★★

기상청 점검 시간 결측치(-999) 안전 대체와 기온 슬라이더 즉시 반응형 인터랙션

점검 시간에 전송되는 -999 결측치나 통신 실패를 감지해 계절 평균 온도로 자동 보정하고, 사용자가 슬라이더를 움직일 때마다 실시간으로 옷차림 카드가 부드럽게 재계산되는 양방향 인터랙션을 완성합니다.

실전 함정: -999를 숫자 그대로 연산에 투입하면 "체감온도 -1020도이므로 우주복을 입으세요" 같은 치명적 오류가 발생합니다!
실전 AI 프롬프트 (원클릭 복사)
[역할] 너는 결측치 처리(Data Imputation)와 반응형 UI 이벤트 처리를 전문으로 하는 시니어 프론트엔드 개발자야. [상황 및 요구사항] 1. 기상청 API에서 기온(T1H) 값이 -999(점검 결측치)이거나 null로 들어올 때, 직전 관측치 또는 기본 안전값(20℃)으로 자동 대체하는 safeTemperature(rawVal, fallback) 유틸 함수 만들기 2. 화면의 <input type="range"> 기온 슬라이더의 input 이벤트 리스너를 작성하여, 슬라이더를 드래그하는 순간 실시간으로 기온 뱃지와 5단계 옷차림 추천 카드가 즉시 업데이트되도록 연결하기 [요청 사항] 1. 결측치 방어 로직과 슬라이더 실시간 업데이트 이벤트 리스너를 자바스크립트로 구현해 줘. 2. 실무에서 결측치(Missing Value)를 방치했을 때 어떤 비즈니스 사고가 발생하는지 쉬운 예시로 설명해 줘. 3. 매 줄마다 초보 학생을 위한 친절한 한국어 주석을 달아줘.
