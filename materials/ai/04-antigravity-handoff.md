# Antigravity CLI 웹 교재 제작 인계 명세

이 문서는 교육과정 설계가 승인된 뒤 실제 HTML 교재를 만드는 순서를 정의한다. 현재 단계에서는 실행하지 않는다.

## 책임 경계

- 교사: 원고와 평가 기준 승인, 실제 수업 적합성 판단
- Hermes Agent: 주차 원고 작성·검수, 누락 검사, Antigravity 작업 단위와 완료 조건 관리
- Antigravity CLI: 승인된 원고를 HTML·CSS·JavaScript와 인터랙션으로 구현
- Antigravity는 교육 내용을 임의로 추가·삭제하거나 정답 정책을 변경하지 않는다.

## 제작 단계

### 0단계 — 설계 승인

- 24주 순서, 용어, 무료 도구 정책, 안전 원칙 확정
- 학생용·교사용 공개 범위 확정
- 사이트의 기존 내비게이션·로그인·배포 방식 조사
- 결과: 승인된 과정 설계와 미해결 결정 목록

### 1단계 — 디자인 시스템과 공통 셸

- 과정 홈, 주차 페이지, 교사용 페이지의 공통 레이아웃 설계
- 색상, 글자 크기, 간격, 카드, 버튼, 코드 블록, 상태 표준 정의
- 모바일·키보드·스크린리더·색 대비 기준 포함
- 결과: 내용이 비어 있는 공통 페이지 셸과 구성요소 목록

### 2단계 — 1주차 기준 페이지

- `02-content-architecture.md`의 학생 페이지 표준 순서를 모두 구현
- 복사 버튼, 힌트, 체크리스트, 진행 저장, 회고 입력을 실제로 동작시킴
- 교사용 콘텐츠는 분리된 경로와 접근 정책에 맞춤
- 결과: 이후 주차가 복제할 수 있는 완성도 높은 1주차 기준 페이지

### 3단계 — 사용성·접근성 검증

- 작은 화면, 키보드만 사용, 확대, 긴 코드, 복사 실패, 저장 실패를 점검
- 중학생 1–2명이 안내 없이 핵심 실습을 찾고 진행할 수 있는지 관찰
- 결과: 수정된 템플릿과 검증 기록

### 4단계 — 2–6주차 제작

- AI 리터러시와 웹 기초 원고를 주차별로 구현
- 각 주차의 결과물이 다음 주차 시작 파일과 자연스럽게 연결되는지 검사
- 결과: 첫 학습 단계 공개 후보

### 5단계 — 7–18주차 제작

- 실행 가능한 코드 예제와 의도적으로 오류가 있는 디버깅 샘플 포함
- Codex CLI 실습에는 운영체제별 안내와 위험 명령 경고 포함
- API 실습에는 키 없는 로컬 대체 데이터 포함
- 결과: 코딩·AI 협업·Agent 단계 공개 후보

### 6단계 — 19–24주차 프로젝트 스튜디오

- 제안서, 요구사항, 테스트, 사용자 피드백, 회고 템플릿 구현
- 프로젝트 상태와 게이트 통과 여부를 시각화
- 발표 체크리스트와 포트폴리오 내보내기 제공
- 결과: 최종 프로젝트 운영 페이지

### 7단계 — 통합 검수와 배포

- 24주 링크, 이전·다음 이동, 진행 상태, 인쇄, 모바일을 전체 점검
- 학생용 페이지에서 교사용 답안이나 비밀 정보가 노출되지 않는지 검사
- 외부 서비스 중단 시 핵심 학습이 가능한지 확인
- 사이트의 기존 자료 목록에 연결하고 배포 후 연기 테스트 수행
- 결과: 운영 가능한 첫 릴리스와 변경 로그

## 주차별 Antigravity 작업 요청 템플릿

```text
목표: 승인된 N주차 원고를 온라인 학습 페이지로 구현한다.

입력:
- N주차 학생용 원고
- N주차 교사용 원고
- 공통 디자인 시스템과 페이지 템플릿
- 사이트의 기존 경로 및 개발 규칙

필수 구현:
- 표준 섹션 순서와 모든 원고 보존
- 코드·프롬프트 복사 및 접근 가능한 성공 안내
- 단계별 체크리스트와 로컬 진행 상태
- 단계적 힌트, 오류 연구소, 회고 입력
- 모바일 및 키보드 사용 가능
- 이전·다음 주차와 과정 홈 이동

제약:
- 승인되지 않은 교육 내용이나 외부 의존성 추가 금지
- 유료 계정 필수화 금지
- API 키를 클라이언트 코드에 포함 금지
- 학생용 페이지에 교사용 답안 노출 금지
- 관련 없는 기존 파일 수정 금지

검증:
- 페이지 로드 오류 없음
- 모든 내부 링크와 복사 버튼 작동
- 체크 상태 새로고침 후 유지
- 작은 화면에서 가로 스크롤 없이 핵심 콘텐츠 사용
- 키보드로 모든 기능 접근
- 실습의 기대 결과와 제공 코드 일치

완료 보고:
- 변경 파일 목록
- 구현한 섹션과 상호작용
- 수행한 테스트와 결과
- 남은 문제 또는 교사 결정 필요 사항
```

## 주차 페이지 완료 조건

- 학습 목표, 핵심 개념, 교사 시연, 학생 실습, 프롬프트, 미션이 원고와 일치한다.
- 예상 문제와 해결 방법이 오류 연구소 또는 교사용 지침에 반영된다.
- 결과물, 복습, 확장 과제, 다음 주 연결이 빠지지 않는다.
- 복사한 프롬프트에는 학생이 바꿀 위치와 결과 검증 질문이 있다.
- 코드 예제는 실행해 확인했고 오류 상태도 설명한다.
- 학생이 완료 여부를 확인하고 진행 상태를 다시 불러올 수 있다.
- 모바일·키보드·색 대비·축소 동작을 확인했다.
- 외부 API가 실패해도 대체 실습으로 목표를 달성한다.
- 교사용 정답과 민감 정보가 학생 번들에 포함되지 않는다.

## Hermes의 제작 관리 체크포인트

1. 원고 완성: 모든 필수 필드와 120분 분량 확인
2. 교육 검수: 개념 정확성, 연령 적합성, 무료 대체 경로 확인
3. 구현 요청: 한 번에 한 주차 또는 공통 구성요소 하나만 전달
4. 구현 검수: 원고 누락과 임의 변경 여부 확인
5. 실행 검수: 코드·링크·상태·오류 흐름 확인
6. 교사 승인: 수업 운영성과 답안 공개 범위 확인
7. 릴리스: 변경 로그와 복구 가능한 버전 기록

## 1주차 제작을 시작하기 전 필요한 결정

- 웹사이트의 공통 헤더·로그인·진행 저장 방식을 재사용할지 여부
- 교사용 자료의 인증 방식과 URL 정책
- 학생 코드 실행을 브라우저 내에서 지원할지, 로컬 실행 안내만 제공할지
- 회고·제출물을 서버에 저장할지 브라우저에만 저장할지
- 지원할 최소 화면 크기와 브라우저
- 콘텐츠 수정 승인 및 버전 표기 방식
